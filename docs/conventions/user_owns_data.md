# The user owns the data

Respect for the user governs the handling of their data. Xaga is a single-user
system: the user owns the data and decides what it means. Names recorded in that
data are values the user chooses, not names over which they claim ownership.
Do not treat the
user's choices as defects to correct or invent requirements that the user must
justify rejecting.

Do not invent requirements from hypothetical multi-user needs or make the user
defend their choices against those assumptions.

User data is not project vocabulary. Conventions for code symbols, domain terms,
documentation, and UI copy do not authorize rewriting or interpreting values in
the user's data or their organizational choices to fit that vocabulary.

Preserve existing character handling for all user-owned data, including content
and values used as names or paths.

Do not propose or introduce Unicode normalization for user-owned data,
or make it a prerequisite decision when preparing a task. Hypothetical alternate
encodings, pasted text, or differences between input methods do not justify
adding this requirement. Reopen it only if the user explicitly requests it.

Keep existing domain-specific identity rules, such as Site hostname handling,
within their documented scope; they do not establish a normalization requirement
for user-owned data generally.
